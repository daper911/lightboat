# 07 里程碑与验收

总工作量约 **3–4 周**（安卓第一期），按里程碑推进，每一步都要有能装到手机上的 APK 才算完成。

| 里程碑 | 内容 | 工作量 | 验收标准 |
|---|---|---|---|
| **M0 环境** | 建仓库，搭 Docker 构建环境，用**原版 FlClash**打出 arm64 debug 包 | 0.5–1 天 | 原版 FlClash 装到你的手机上能打开；手动导入轻舟订阅后能连接（证明环境与内核没问题） |
| **M1 原型** | 包名、App 名改成轻舟（debug 签名）；登录页；登录后自动拉订阅、一键连接；去掉 Firebase | 1–2 天 | 用测试账号登录，点一下就连上；你在手机上实际感受一下，**决定是否继续完整开发** |
| **M2 品牌化与精简** | 轻舟配色、图标、启动页；首页（套餐卡片、连接按钮、线路选择）；隐藏 FlClash 的高级界面；滑块验证码 | 2–3 天 | 界面符合 [08](08-brand-and-ui.md)；输错 3 次后的滑块流程能走通 |
| **M3 账号与运营** | 我的页：套餐详情、续费跳转、公告、教程、客服；登录失效处理；订阅定时更新；检查更新；导出日志；关于页 | 3–4 天 | [06](06-testing.md) 中「账号」「订阅与套餐」「其他」的用例全部通过 |
| **M4 稳定性** | 后台保活与引导、网络切换、国产系统适配、深色模式、英文文案 | 约 1 周 | 「连接」用例在至少 3 个品牌的手机上通过；24 小时不断线 |
| **M5 发布** | 正式签名证书、版本号、官网下载与 `latest.json`（需要主项目配合）、源码公开、安装教程 | 2–3 天 | 用户从官网下载、安装、登录、连接全流程顺畅；旧版本能升级 |

## 第一步之前

- [ ] 运营方确认 [01 §10](01-product-requirements.md) 中的 App 名称和**包名**（M1 就要用；正式发布后不能改）；
- [x] 建仓库（2026-10-04：私有仓库 `daper911/lightboat-android`，导入方式，见 [04 §1](04-dev-environment.md)）；
- [ ] 准备至少一台安卓真机，打开「允许安装未知来源应用」。

## 原型阶段（M0 + M1，1–2 天）的意义

先做一个「能登录、能一键连接」的 APK，在真机上用一用再决定要不要完整开发。如果体验和直接用 FlClash 差别不大，或者发现关键障碍（比如某些机型装不上），可以在这里停下，成本只有一两天。

## 第二期（不在本次范围）

- 桌面版（Windows / macOS / Linux），约 1–2 周；
- App 内原生注册、WebView 付款、邀请返利；
- 面板托管规则集、远程地址列表（需要主项目配合）。
